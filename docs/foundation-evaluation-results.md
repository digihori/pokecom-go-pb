# 共通数値基盤の技術試作・初回評価結果

実施日: 2026-11-03

続報: [除算の切り分けと補完候補の評価](decimal-division-evaluation.md)で、追加精度方式の反例と正確な商・余りを使う候補の結果を記録した。以下は初回評価時点の記録。

## 結論

KMPの共通数値コードは、手元のXcode 26.6でiOS Simulator上の実行とiosArm64向けリンクまで成立した。一方、**bignum 0.3.10の12桁指定の除算には、独立参照値との不一致があり、そのまま本採用しない**。丸めの未知なPB実機互換とは別に、指定した比較モデルを満たさない問題として扱う。

製品のインタープリタは未実装。試作は[prototypes/foundation](../prototypes/foundation/README.md)に分離し、評価コード・独立参照値の生成手順・再現コマンド・ログを残した。

## 確認した構成

| 項目 | 実施した構成 |

| ホスト | macOS / Apple Silicon arm64 |
| JDK | JBR 21.0.11 |

Compose、AGP、Android、各OSの配布物はまだ構成していない。この結果で評価計画の全バージョン組合せを検証済みとはしない。Coroutinesは依存解決・リンクのみで、セッション制御の動作評価は未実施。

## 実行結果

| 対象 | 結果 | 読み方 |
| --- | --- | --- |
| JVM共通コード・試験コンパイル | 成功 | macOS上のJVMのみ |
| iOS Simulator Debug試験リンク・実行 | 成功（実行基盤）／数値試験に失敗あり | 実行できたことと数値の合格を分ける |
| iosArm64 Debug試験リンク | 成功 | 実機での実行・署名は未確認 |
| Simulator／実機向けRelease Frameworkリンク | 両方成功 | 最適化リンクのみ。Releaseでの実行試験ではない |
| Python decimal参照の固定60ベクトル | JVM・iOSとも一致 | 指定モデルのこの入力範囲に限る |
| JVMのJava BigDecimal独立比較1,000件 | 44件不一致 | 全件を比較し、失敗を検出。PB範囲外の値も含む |
| 共通の`2/3`最小例 | JVM・iOSとも不一致 | 同じライブラリの問題が両環境で再現 |
| 追加精度の診断 | JVMの除算1,000件およびJVM／iOSの既知2例で一致 | 一般的な解決の保証ではない |

通常試験はJVMで10メソッド中2件失敗、iOSで8メソッド中1件失敗。全体のGradleコマンドは失敗終了している。失敗試験を無効化したり、誤答へ期待値を合わせたりしていない。

### 除算の最小再現例

`BigDecimal.parseString("2").divide(BigDecimal.parseString("3"), DecimalMode(12, ROUND_HALF_AWAY_FROM_ZERO))`

- 指定モデルの期待値：`0.666666666667`
- 実際：`0.666666666666`

別の例：`-241365E-45 / 377629E-66`

- Java BigDecimalの12桁HALF_UP：`-6.39159068822E20`
- bignumの同条件：`-6.39159068821E20`

これらは「PBがどの丸めを使うか」とは別の、指定したライブラリ丸め条件との比較である。`divide`／`roundDiscarded`周辺の余りの扱いが調査対象となるが、根本原因を確定・修正したものではない。[評価した版の公式ソース](https://github.com/ionspin/kotlin-multiplatform-bignum/blob/0.3.10/bignum/src/commonMain/kotlin/com/ionspin/kotlin/bignum/decimal/BigDecimal.kt)

### 追加精度を使う診断

24桁で除算した後に12桁へ丸める別経路では、今回のJVM除算1,000件と共通の既知2例が参照値に一致した。ただし二重丸め、丸め境界に極端に近い値、より広い入力桁数等を保証していない。通常経路の代わりに黙って使わず、修正候補の比較材料に留める。

## 数値APIと互換仕様

- 四則演算・精度・丸め指定・十進文字列の往復は利用可能。確定した比較モデルの試験を追加できる。
- PBの範囲制限はライブラリ任せにできない。`1E-99 / 10 = 1E-100`も表現できることを確認した。
- `BigDecimal.kt`には整数べきがある一方、同ファイルの平方根・対数の例はコメントアウトされている。全数学関数が提供されるという前提は置かず、公開API全体と補完方式を別途確認する。
- 取得したMaven POMのライセンス記載はApache License 2.0。製品導入時の同梱表示・全推移依存の確認は残す。
- 内部12桁、表示桁数、LCD 12文字を統合していない。PBの丸め方式・タイミング、範囲外エラーの仕様は引き続き未決。

## 評価計画への対応

E0・E1の主要経路を確認し、E2で数値候補の問題を発見した段階。I01は共通依存のリンク、I02はSimulatorでの実行まで確認したが、数値の合格条件は満たさない。I07は十進文字列のJSON往復のみを確認した。

次は数値候補の比較・除算問題の切り分けを優先し、E3のCompose画面追加はまだ行わない。iOS実機、Release実行、Android、Windows／Linux JVM、最低OS、特殊記号の往復、セッション／LCD、バックグラウンド復帰、停止応答・メモリ計測は未実施。
