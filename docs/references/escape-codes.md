# 特殊記号・エスケープ表現

更新日: 2026-11-03

ユーザー指定により [pbsavea.pl v0.5の保存原本](pbsavea-v0.5.pl) を基準に整理した。以下の表記と内部コードは静的なコード読解で確認済み。グリフの見た目は別途、公開キャラクタ表や実機で照合する。これは新アプリの実装ではなく、入力・保存・転送に使う要求仕様資料。

## 1. 定義済みエスケープ

表の各表記は、バックスラッシュ1文字＋大文字英字2文字。大文字小文字は区別される。

| ソース上の表記 | PB内部コード（16進） |
| --- | --- |
| `\UA` | 05 |
| `\GE` | 0B |
| `\LE` | 0D |
| `\NE` | 0F |
| `\PI` | 1B |
| `\EM` | 1E |
| `\EX` | 1F |
| `\CI` | 60 |
| `\SG` | 61 |
| `\DG` | 62 |
| `\TR` | 63 |
| `\CR` | 65 |
| `\DV` | 66 |
| `\SP` | 67 |
| `\LA` | 68 |
| `\HT` | 69 |
| `\DI` | 6A |
| `\CL` | 6B |
| `\MU` | 6C |
| `\OM` | 6D |
| `\DA` | 6E |
| `\RA` | 6F |
| `\SQ` | 72 |
| `\DT` | 77 |
| `\BX` | 79 |

計25種類。定義は原本5〜23行、入力の処理は105〜118行および251〜267行。

`\SP`は0x67に対応する特殊記号で、通常の空白ではない。通常の空白文字は0x00。

## 2. バックスラッシュと代替表記

| ソース上の表記 | 内部コード | スクリプトでの扱い |
| --- | --- | --- |
| `\\` | 71 | バックスラッシュ自体。2文字で記述する |
| `^` | 05 | `\UA`と同じコード。コメントでは上向き矢印への変換として説明 |
| `>=` | 0B | 引用文字列・REMとして扱う部分以外で`\GE`へ置換 |
| `<=` | 0D | 同様に`\LE`へ置換 |
| `<>` | 0F | 同様に`\NE`へ置換 |
| `!=` | 0F | 同様に`\NE`へ置換 |

定義済みエスケープ、`\\`、`^`は引用文字列として扱う部分でも変換される。一方、引用文字列内の`>=`等は比較演算子へのまとめ変換を受けず、それぞれの通常文字として変換される。

スクリプトのREM分岐は入力変換上の扱い。PBの命令としてREMを採用するという仕様ではない。

## 3. 通常文字と文脈の注意

- 文字としてのコロンは0x5F。引用外で命令区切りとして処理されるコロンは0xFE。
- 予約語表の`LEN\(`、`VAL\(`、`MID\(`にあるバックスラッシュはPerl正規表現用。BASICソースには`LEN(`、`VAL(`、`MID(`と書く。上記の特殊記号エスケープとは区別する。
- 本資料のエスケープはPBの予約語トークンではなく、テキストでPBキャラクタを表す入力表現。

## 4. 新アプリへ反映する要求と未決事項

確定した要求:

- 特殊記号のテキスト表記は、このスクリプトのエスケープ定義に従う。
- デスクトップとPlayer、保存・テキスト読込・QR・WAVで同じ表記と内部コードの対応を使う。

確認・決定が必要な事項:

- 各内部コードに対応する正確なキャラクタの形。名称の推測でグリフを決めない。
- 未知のエスケープ、不完全な入力、未対応文字をどう通知するか。旧スクリプトは未知文字を0x00へ変換し、末尾の不完全なエスケープを出力しない場合がある。この黙示的な処理まで踏襲するかは未決。
- 出力時の正規形。例えば0x05を`\UA`と`^`のどちらで出すか、比較記号をエスケープと代替表記のどちらで出すか。
- 同じ意味の表記を再保存時に統一するか、元のテキスト表記を保持するか。
- Unicode記号の直接入力を追加で許容するか。現時点で採用要求はない。
